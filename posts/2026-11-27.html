1. FCC, SpaceX의 우주 AI 데이터센터 위성 계획 허가

미국 연방통신위원회(FCC)는 11월 25일 SpaceX의 Starmind 계획에 최대 100만 개의 궤도 연산 모듈을 배치·운영할 수 있는 허가를 내렸습니다. SpaceX는 우주에서 데이터를 처리해 지상에서 활용하는 데이터센터 성좌를 구상하고 있습니다. FCC의 명령은 첫 위성을 2033년 11월 25일까지 궤도에 배치해 운영할 것을 요구합니다.

  • 이번 결정은 조건이 붙은 허가입니다. 실제 위성 발사나 전체 사업의 완성을 뜻하지 않으며, 막대한 발사·운영 비용과 방열 등 기술적 난제가 남아 있습니다.
  • 미국천문학회는 위성의 밝기와 수가 천문 관측과 밤하늘에 미칠 영향, 발사·재진입에 따른 대기오염, 궤도 충돌 위험을 우려했습니다.
  • AP는 과학자들의 회의적인 시각과 함께 FCC가 궤도 잔해 규정과 공익 기준을 충족한다고 판단한 점을 전했습니다.

AI 연산 수요를 새로운 장소에서 충당하려는 구상이지만, 허가의 규모와 실제 구현 가능성·환경 영향은 별개로 지켜봐야 합니다.

2. Character.AI 파산 매각, 사적인 채팅 데이터가 쟁점

미국 42개 주 법무장관과 워싱턴 D.C.가 Character.AI 파산 절차에서 플랫폼과 이용자 데이터의 제안된 매각 조건에 반대했습니다. 오리건 법무부에 따르면 문제의 자료에는 미국 계정 2,100만 개 이상의 대화 기록이 포함되며, 그중 210만 개 이상은 미성년자 명의로 등록됐습니다.

  • 법무장관들은 민감한 채팅이 적절한 보호장치 없이 양도될 수 있다고 우려하며 법원에 매각 조건을 거부하도록 요청했습니다. 이는 주 정부 측의 주장과 신청입니다.
  • 자산 매각 절차는 아직 진행 중이며, 제안된 거래나 대화 데이터 이전이 최종 승인됐다고 단정할 수 없습니다. 법원이 소비자 개인정보 옴부즈먼을 지정해 보호 조치를 검토하도록 한 사실도 주 정부가 발표했습니다.
  • 이 사건은 이용자 커뮤니티에서도 큰 반응을 얻었습니다. 관련 Reddit 게시물 하나는 확인 시점에 445개 추천을 받았습니다.

대화형 AI에 남긴 고백과 일상 기록은 서비스 운영 주체가 바뀌거나 파산하는 상황에서도 중요한 개인정보 문제로 남습니다. 이용자는 서비스 공지와 법원 절차를 확인하고 제공되는 내보내기·삭제 설정을 살펴볼 수 있습니다. 삭제 요청만으로 모든 백업이나 법적 보존분이 즉시 제거된다고 가정해서는 안 됩니다.

3. Google Workspace, AI 에이전트의 공식 연결 경로 정비

Google은 11월 24일 Workspace MCP 서버와 공식 CLI의 정식 제공을 발표했습니다. Gmail·Drive·Docs·Sheets·Slides·Calendar·Chat·Tasks 등에서 에이전트가 작업하도록 연결하고, 관리자가 접근과 승인·감사 설정을 관리하는 방향입니다.

  • Google의 새로운 Workspace AI Tools Addendum은 해당 범위의 AI 에이전트가 기존 REST API 대신 Google MCP 서버 또는 CLI를 사용하도록 요구하며, 기술적 적용은 2027년 2월 1일 시작될 예정입니다.
  • 개발자 문서에 따르면 그날부터 REST API를 직접 호출하는 AI 에이전트는 요금제와 관계없이 Standard Tier 할당량으로 제한됩니다. 해당 약관과 예외, 각 API별 한도는 직접 확인해야 합니다.
  • Google은 새 할당량 대시보드와 Standard·Scaled 사용 단계를 안내하며, Scaled 단계의 과금 시행일을 2027년 4월 1일로 설명했습니다. MCP 도구 호출 하나가 내부적으로 여러 API 요청을 소비할 수 있습니다.

어제 다룬 Claude의 MCP 확장이 서버가 스킬을 전달하는 방식에 초점을 뒀다면, 이번 Google 발표는 Workspace 데이터에 접근하는 앱의 경로·할당량·관리 통제를 바꾸는 소식입니다. 기존 자동화가 영향을 받는지는 실제 API 경로와 계정 설정을 확인해야 합니다.

4. Anthropic, Claude Messages API를 Rust로 전환

Anthropic은 11월 25일 Claude의 Messages API를 Python에서 Rust로 옮긴 과정을 공개했습니다. 회사에 따르면 Claude가 핵심 요청 경로의 첫 버전을 약 일주일 만에 작성했지만, 이후 더 어려운 과제는 기존 서비스와 동등하게 동작하는지 검증하는 일이었습니다.

  • 기존 Python API가 계속 변경되고, 같은 입력에도 모델 응답이 달라질 수 있으며, 고객 요청을 직접 읽을 수 없다는 제약을 고려해야 했습니다.
  • Anthropic은 운영 API를 비교 검증에 활용하고 차이를 발견하면 에이전트에 수정 작업을 맡기는 방식으로 전환했다고 설명합니다.
  • 회사 측은 전환 후 요청당 CPU 사용량이 약 70% 줄고 첫 토큰까지의 중앙값 시간이 약 20% 단축됐다고 보고했습니다. 이는 해당 서비스의 자체 측정이며 모든 API나 워크로드의 결과는 아닙니다.

핵심은 코드 생성 속도만이 아니라 실제 서비스에 영향을 주는 차이를 찾아낼 검증 체계입니다. 에이전트가 코드를 고치는 흐름에서도 테스트와 관찰 가능한 근거가 배포 판단을 뒷받침해야 합니다.
