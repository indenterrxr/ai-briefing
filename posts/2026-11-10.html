11월 9일의 발표는 AI가 서로 다른 세 층에서 동시에 빨라지고 있음을 보여줍니다. Anthropic은 가장 어려운 기술 작업을 겨냥한 Claude Fable·Mythos 5.2를, Meta는 대량의 반복 작업을 맡길 저비용 서브에이전트용 Muse Ember를, NVIDIA는 물리 세계에서 행동을 배우는 오픈 로봇 모델 GR00T 2를 공개했습니다.

1. Claude Fable 5.2·Mythos 5.2 — 더 빠른 고난도 기술 에이전트

같은 기반 모델, 다른 안전 접근권

Anthropic은 Claude Fable 5.2와 Claude Mythos 5.2를 발표했습니다. 두 모델은 같은 기반 모델을 공유하지만, Fable은 광범위한 사용자에게 제공하기 위해 사이버·생물학 분야의 보호장치를 적용했고, 해당 이중용도 연구가 필요한 검증 조직은 프로그램을 통해 Mythos에 접근할 수 있도록 나뉩니다.

  • 효율: Anthropic은 5.1 대비 최대 30% 빠른 출력을 내며, 표준 가격을 입력 100만 토큰당 8달러·출력 40달러로 낮췄다고 밝혔습니다. 선택형 Fast mode는 최대 2.5배의 생성 속도를 목표로 합니다.
  • 작업 배치: Anthropic은 일상적 코딩·지식 업무에는 Opus 5.5부터 시작하고, 매우 복잡한 오픈엔드 기술 과제에는 Fable·Mythos를 쓰라고 권합니다. Fable은 작은 모델을 지휘하는 조언자나 오케스트레이터 역할에도 배치할 수 있습니다.
  • 안전 설계: 사전 배포 평가와 외부 평가를 거쳤고, Fable의 사이버·생물학 분류기는 유지하면서 불필요한 차단을 줄였다고 설명합니다. Mythos의 고위험 역량은 검증 프로그램으로 제한됩니다.
고성능 모델의 공개 방식은 ‘모두에게 같은 기능’보다, 사용 목적과 감독 역량에 따라 접근과 보호장치를 다르게 두는 형태로 세분화되고 있습니다.

2. Meta Muse Ember — 대량 실행을 맡길 소형 멀티모달 모델

큰 모델은 계획하고, Ember는 반복 작업을 처리한다

Meta는 Muse Ember를 공개했습니다. 도구 호출, 코딩 하위 작업, 라우팅, 문서 추출과 요약처럼 에이전트가 반복하는 실행 단계를 겨냥한 경량 모델입니다. 텍스트뿐 아니라 이미지·오디오·비디오·PDF 입력을 다루며, Meta는 큰 모델이 계획을 세우고 Ember가 대량의 실행을 처리하는 조합을 제시합니다.

  • 규모와 비용: 100만 토큰 컨텍스트, 최대 51만 2천 토큰 출력을 지원하며 입력 100만 토큰당 0.10달러, 출력 0.50달러로 책정됐습니다.
  • 적합한 역할: 대규모 문서 묶음에서 정보 추출하기, 제한된 코딩 하위 과제, 반복적 도구 호출처럼 결과 형식이 비교적 정해진 일을 많이 처리할 때의 비용·지연을 낮추는 데 맞춰졌습니다.
  • 평가 읽는 법: Meta는 자체·외부 벤치마크에서 경쟁 모델 대비 효율을 강조합니다. 다만 에이전트 성능은 하니스, 도구 권한, 작업 분해 방식에 크게 좌우되므로 실제 도입 전에는 팀의 데이터와 업무 흐름에서 별도 검증이 필요합니다.

이 발표가 시사하는 변화는 단순히 ‘더 작은 모델’이 아닙니다. 한 모델에 모든 판단을 몰아주기보다, 고비용 추론은 계획에, 저비용 모델은 반복 실행에 배치하는 모델 포트폴리오가 제품 설계의 기본값이 되고 있습니다.

3. NVIDIA GR00T 2 — 시뮬레이션에서 배운 행동을 현실 로봇으로

월드 액션 모델과 에이전트형 로보틱스

NVIDIA는 CoRL 2026에서 GR00T 2를 발표했습니다. Cosmos를 기반으로 한 오픈 월드 액션 모델로, 주변 환경을 인지하고 행동의 결과를 예측하며 다단계 조작 작업을 수행하도록 설계됐습니다. 로봇·인간 데이터와 NVIDIA의 공개 1인칭 데이터 10만 시간을 활용해 학습됐다고 회사는 설명합니다.

  • 시연 효율: NVIDIA의 50개 과제 평가에서 특정 작업용 시연 없이 40개 과제를 한 번 이상 수행했고, 시연 한 번으로 평균 71%, 다섯 번으로 95% 성공률을 기록했다고 발표했습니다.
  • 몸체 간 전이: 인간 시연에서 배운 기술을 서로 다른 로봇 몸체로 옮기는 것이 목표입니다. 이는 로봇별로 새 데이터를 대규모 수집해야 하는 부담을 줄이려는 접근입니다.
  • 에이전트 연결: 지원 도구와 API를 통해 언어 에이전트가 기술을 순서대로 실행하고 오류에서 회복하도록 구성할 수 있습니다. Isaac Lab 3.0·벤치마크·데이터 워크플로도 함께 공개됐습니다.

시뮬레이션 성적과 실제 현장 신뢰성은 다릅니다. 하지만 모델, 물리 시뮬레이션, 시연 데이터, 작업 오케스트레이션을 하나의 공개 도구 흐름으로 묶었다는 점은 범용 로봇 개발의 진입 장벽을 낮출 수 있습니다.

실무자를 위한 체크포인트

  • 고성능 모델 도입 시에는 모델명보다 어떤 작업을 누구의 감독 아래 허용할지를 먼저 정의하세요.
  • 대량 에이전트 워크플로는 계획 모델과 실행 모델을 분리해, 품질·비용·지연을 각각 측정하는 구조가 유리합니다.
  • 물리 AI는 데모 영상보다 실패 시 정지·복구·사람 개입 규칙과 실제 환경 검증 범위를 우선 평가해야 합니다.
